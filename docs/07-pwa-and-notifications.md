# SAIRA: PWA and Notifications

## 1. What a PWA is (for the learner)

A Progressive Web App is a normal website that can behave like an installed app. It needs: HTTPS, a **web app manifest** (name, icons, theme colour, start URL), and a **service worker** (a script the browser runs in the background that caches files for offline use and can receive push messages). Once installed it gets its own icon and window, opens offline, and can show notifications.

## 2. Manifest

Generated by `vite-plugin-pwa` (`manifest` option):
```json
{
  "name": "SAIRA: DSA Study Tracker",
  "short_name": "SAIRA",
  "description": "Daily DSA sheet, streaks and reminders",
  "start_url": "/today",
  "scope": "/",
  "display": "standalone",
  "orientation": "any",
  "background_color": "#131315",
  "theme_color": "#131315",
  "icons": [
    {"src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png"},
    {"src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png"},
    {"src": "/icons/maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable"}
  ],
  "shortcuts": [
    {"name": "Today", "url": "/today"},
    {"name": "Sheet", "url": "/sheet"},
    {"name": "Revision", "url": "/revision"}
  ]
}
```
Copy `brand/*.png` into `public/icons/`. Add `<meta name="theme-color">`, `apple-touch-icon`, and `apple-mobile-web-app-capable` tags.

## 3. Service worker (`src/sw.ts`, `injectManifest`)

- Precache the app shell and bundled seed JSON; runtime cache fonts and images (stale-while-revalidate).
- Navigation fallback to `index.html` (SPA), except `/__/` Firebase paths.
- **Never cache Firestore/Auth network calls** (the Firestore SDK has its own offline store).
- `registerType: 'prompt'`: show an "Update available, reload" toast; never reload silently mid-edit.
- FCM background handler in the same SW (`firebase/messaging/sw` with `onBackgroundMessage`), plus `notificationclick` that focuses/opens `/today?coach=<slot>`.

## 4. Reminders: three layers, be honest about each

| Layer | Works when | How |
|---|---|---|
| **A. In-app coach overlay** | App/tab open or installed app running | A scheduler in `src/lib/schedule.ts` computes the next slot (default 08:30 and 19:00 in the user's tz), `setTimeout` to it, recomputes on focus/visibility change, wakes on `visibilitychange` to catch missed slots (fires if ≤ 30 min late). Shows the coach overlay and speaks the line |
| **B. System notification (local)** | Page/SW alive and permission granted | `registration.showNotification()` with coach icon, actions `Start` / `Snooze` |
| **C. Background push (FCM)** | App closed, device online, permission granted, PWA installed (required on iOS 16.4+) | Server sends a data message at the scheduled time; the SW shows the notification |

Limits to state in Settings and README: a browser cannot draw a character over the desktop outside the browser; the "woman" appears in the in-app overlay and as the notification icon/image. Delivery of push can be delayed by the OS. Speech may be blocked until the user has interacted with the page, so text and a "Play voice" button are always shown.

## 5. Permission UX

Ask for notification permission only after the learner has used the app (e.g. after completing the first item) with a pre-prompt explaining the 8:30 AM and 7:00 PM nudges. If denied, show how to re-enable and keep layers A working. Never ask repeatedly.

## 6. Scheduling rules

- Defaults: morning **08:30**, study **19:00**, `Asia/Kolkata`. Both editable; days of week selectable; quiet hours optional.
- Skip a slot if today's target is already met.
- **Snooze** re-arms in 15 min (configurable), max 3 snoozes per slot.
- A missed day triggers the `nudge_missed` line at the next evening slot, once.
- Store `lastFiredSlot` per day to avoid duplicates across tabs/devices (write to `users/{uid}/meta/reminderState`).

## 7. Background push implementation (FCM)

1. Firebase console → Cloud Messaging → generate **Web Push certificate** → put the public key in `VITE_FIREBASE_VAPID_KEY`.
2. Client: `getToken(messaging, { vapidKey, serviceWorkerRegistration })`; save token to `users/{uid}/devices/{deviceId}` `{ token, platform, tz, createdAt, lastSeenAt }`; refresh on app start; delete on sign-out.
3. Sender (choose one):
   - **Option A (free): GitHub Actions** `push-reminders.yml`, cron every 15 minutes (`*/15 * * * *`, UTC). A Node script using `firebase-admin` (service account in `FIREBASE_SERVICE_ACCOUNT` secret) loads each user's settings, finds users whose local reminder time falls in the current 15-minute window, skips users who already hit their goal, and sends via `messaging().sendEachForMulticast`. GitHub cron can run late and scheduled workflows in public repos are paused after ~60 days without repo activity; keep the repo private or active, and treat delivery as best-effort.
   - **Option B: Cloud Functions scheduled function** (Cloud Scheduler) on the Blaze plan with a card on file; more reliable timing; usage at this scale should stay within free quotas but verify current pricing.
4. Message payload: `data` only (`slot`, `line`, `url`), the SW builds the notification (icon `/icons/icon-192.png`, `image` coach art, `tag` = `saira-<slot>-<dayKey>`, `renotify:false`).
5. Remove invalid tokens on `messaging/registration-token-not-registered`.

Reference times in UTC for the default IST schedule: 08:30 IST = 03:00 UTC; 19:00 IST = 13:30 UTC.

## 8. Install UX

Capture `beforeinstallprompt`, show an "Install SAIRA" button in the top bar and Settings; on iOS show a one-time hint ("Share → Add to Home Screen"). Detect `display-mode: standalone` to hide the button.

## 9. Testing checklist

- Lighthouse: installable ✔, service worker ✔, offline start URL ✔.
- DevTools → Application: manifest valid, SW active, icons load, maskable preview OK.
- Offline: toggle offline, reload `/today` and `/sheet`, tick an item, go online, verify sync.
- Reminder preview button fires overlay, speech, and a test notification.
- Time-travel test: unit test the scheduler with a fake clock across midnight and across a missed slot.
